# Auston office customer pack

Ids, file names and install names keep the historical `austin` spelling; the customer is Auston Realty (澳仕登地產). Revision 3 changes display text only: the pack title and the Auston spelling in the REI Cloud navigation skill and its license.

`realbud-austin-office-v1.json` is a portable, instruction-only pack for the three Auston business outcomes: bank references and REI handoff; bills and calendar; morning priorities and unanswered follow-ups. Four typed preparation recipes implement the local supplied-source stage. The included upstream inbox instruction text retains its license and is installed with a bounded RealBud native skill wrapper.

Revision 2 adds `rei-cloud-navigation`, a first-party instruction-only skill for the Auston Realty add-on, not RealBud core. It is derived from the read-only [REI Cloud map](../../../docs/REI-CLOUD-MAP-2026-09-24.md); its source, `site-map.json`, provenance and license live in `../austin-accounts/support/rei-cloud-navigation/`. It covers the account-scope check, sign-in pause, stable row selectors, overlays, edit locks, routes for the three workflows, the reports "Export Only" rule and action risk classes. It grants nothing: the RealBud portal fence stays the only authority, and money, send and record-change controls need its per-instance approval.

Revision 6 (`austin-accounts` revision 2) adds `property-management`: the property-management voice, PM rules (no statutory notices, no trust money, no invented legal clock) and property intake format that moved out of RealBud core on 7 October 2026, when core Bud became a neutral business office assistant. Its source and provenance live in `../austin-accounts/support/property-management/`. Plans are unchanged. An office on revision 5 (or `austin-accounts` revision 1) takes it through Schedule → Workflow packs → upgrade preview; re-importing over the older revision is held because an installed revision is immutable. `austin-property` stays without skills so department case preparation can keep using its maintenance plan.

Import through Schedule → Workflow packs → Preview a pack file. Preview checks identifiers, content, existing plans and instruction files. Confirming import installs missing dependencies and leaves plans in shadow with schedules off. Existing edited plans are not overwritten. A conflicting older plan needs explicit reconciliation, not a silent replacement.

Setup distinguishes installed local artifacts, selected-account observations, required inputs and supervised business acceptance. Import performs no bank/mail/account access, model call, source acquisition, payment, message sending or REI import. A local installed status is not proof of a connected workflow or customer acceptance.

Native complete-text skill suggestions for the owned skill can be reviewed under the pack card. Applying or reverting text retains the immutable published baseline and revision history, invalidates dependent plan approvals and clears schedules before switching instructions. Core skills, scripts, deletion, arbitrary files and memory proposals cannot be approved here. Interrupted changes hold work for explicit recovery. This review mechanism does not create an OS sandbox for the worker.

The JSON files are the published source: the app loads them verbatim. `server/customer-pack-definition.test.ts` pins their digests and fails when the embedded skill text drifts from the `austin-accounts` support files. No customer records, credentials, installation paths, browser profiles, schedules or local approvals are exported. Changes to the published pack require a new reviewed pack revision; approved local instruction overrides are separate and are preserved by repair.

## Austin schedule pack (`austin-schedule-v1.json`)

A separate versioned file (`format: realbud-loop-pack`, revision 1) for the six built-in Schedule workflows: bank references (every 2 days, 08:00), weekly bills (Monday 08:00), morning priorities (weekdays, starts 07:30 to be ready by about 08:00), maintenance checks (weekdays 08:30), the supplier list check (fortnightly Monday 08:15 from 12 October 2026) and the inspection draft (first weekday of the month, 09:00). It carries each workflow's plain plan text (what it reads, waits for, who it tells, what needs approval), the required connections (Gmail, Redbark, REI Cloud sign-in in the work browser) and two confirmed rules (maintenance: calendar month by received date; inspections: six-month cycle from the completed date). It holds no customer names, addresses or accounts.

Install it from Schedule → Workflow setup (`server/austin-pack.ts`, `POST /api/austin-pack/install`). Install sets the office timezone from agency setup (default Australia/Brisbane) on each workflow whose time and days still match the pack, and leaves every workflow on or off exactly as it was. A workflow the office retuned keeps its own times. The maintenance month rule is set only while the office has never chosen one. Schedule then shows the Austin setup checklist; each item opens where that step is done. Installing reads no mailbox, bank or portal.
