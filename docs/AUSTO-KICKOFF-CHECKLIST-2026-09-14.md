## What to capture for each CSV correction

| Field | What Kevin supplies |
|---|---|
| File pair / original row | Identifies the same transaction in the raw and corrected files |
| Original description/reference | Exact bank value, including spaces and leading zeros |
| Correct REI reference | Exact value used, or **leave unresolved** |
| Evidence | REI record/report or other approved evidence supporting the match |
| Explanation | Why this reference is correct, and why alternatives were rejected |
| Expected result | Accepted preview/match, rejection, duplicate warning or manual hold |

Useful difficult cases include blank/incorrect/truncated references, a payer with a different name, similar tenant names, multiple properties, partial or combined payments, old tenancy references and duplicate downloads. Also include actual formatting failures: lost leading zeros, changed dates, encoding or altered CSV columns. Request examples that exist; do not ask Kevin to manufacture every case.

Preserve each original unchanged. Use consistent substituted identifiers if redacting, retaining the structure and relationships needed to reproduce the error. Transfer real records only through an agreed restricted location; keep them outside source control and public artifacts. Agree who may see them, which services process them, retention, deletion and backup expiry before using personal data.

## What counts as a successful pilot

- On Kevin-approved examples, each reference suggestion has evidence; known ambiguous cases remain unresolved. The saved reviewed copy preserves amounts, dates, row count/order and all fields except explicitly approved reference changes. Kevin checks actual REI recognition/preview before financial processing.
- Bill results distinguish expected, received, processed, payment arranged and verified paid. Missing checks and uncertainty are visible, with source links and an owner for follow-up.
- The morning list covers the agreed sources and time window, with useful priorities, source links, waiting items and visible incomplete checks.
- Prove login/MFA pause, Stop/takeover, offline/restart recovery and safe repeat runs on the selected office devices. Agree a measured ready-by time using representative volumes.
- If automatic bank acquisition is included, test the actual authorised acquisition route. Manual upload is a useful fallback but does not satisfy that requirement.
- Kevin signs off the agreed examples and a short live pilot before routine use. A suggested pilot is five working days, subject to the selected scope and enough representative cases.
