# Connection sessions and Hermios placement — 1 October 2026

Status: implementation decision and verified discovery, not an authenticated integration or release acceptance. Preserve the existing Hermes worker runtime and managed model route. **Hermios is the CRM**; its account, workspace and record permissions are separate from Hermes and RealBud office membership.

## What is verified

- The current source UI includes a **Hermios CRM — Planned** entry in [Connected apps](../../src/lib/connected-app-catalog.ts), with `connected: false` and no connection action. [You → Office → People & departments](../../src/components/YouPage.tsx) explains the intended workspace binding. These are planning surfaces only; they do not connect an account, grant access or establish installed-app behavior.
- The [Hermios module adapter](../../server/hermios-modules.ts) and [shared contract](../../shared/hermios-modules.ts) exist as a source-only seam. They require a verified company/member/profile/workspace binding and connection generation. The adapter is not mounted in the application; RealBud has no Hermios OAuth transport, token lifecycle, persisted binding or native record route. Earlier fictional contract tests are documented in the [owner status](../HERMIOS-INTEGRATION-OWNER-STATUS-2026-10-01.md).
- Fresh unauthenticated GETs returned **HTTP 200** for the official [authorization-server metadata](https://api.hermios.app/.well-known/oauth-authorization-server), [resource metadata](https://api.hermios.app/.well-known/oauth-protected-resource) and [MCP resource metadata](https://api.hermios.app/.well-known/oauth-protected-resource/mcp). They advertise authorization code, S256 PKCE, refresh tokens and `api`/`profile` scopes; the MCP resource is `https://api.hermios.app/mcp`. The [sanitized discovery receipt](../../outputs/connections-design-2026-10-01/hermios-oauth-discovery.json) records timestamps and public response hashes. Discovery does not prove a registered RealBud client, authenticated profile, deployed module tools or record access.
- The installed Hermios plugin's [setup reference](/Users/yo-da/.codex/plugins/cache/hermios/hermios/0.6.0/references/setup.md) describes one OAuth connection per account/workspace and fresh `get_hermios_profile` verification after switching. Codex owns that plugin's credentials. RealBud must establish its own connection; no Codex credential copying is part of this design.

## What can remain signed in

| Connection | Existing behavior and limit | Required product behavior |
| --- | --- | --- |
| Composio apps, including Gmail | Composio manages OAuth access-token refresh. A revoked/expired refresh grant requires a fresh consent link. `ACTIVE` alone is not a current account-access check. | Show the selected account, last access check and reconnect state. Keep provider tokens in Composio; use its supported execution/proxy path. |
| RealBud work browser | The [native host](../../server/work-browser-host.ts) uses its own persistent browser profile and graceful close to preserve it. The [fictional test receipt](../../outputs/hermes-work-browser-host-2026-10-01-graceful-close/receipt.json) covers cookie survival across reopening, not a bank login. | Reuse that profile and let the website manage its session. Pause for user login/MFA when required. Do not copy personal-browser cookies or promise an indefinitely active session. |
| Hermios native MCP | Public metadata advertises refresh-token support; RealBud has not implemented or exercised it. | Implement protected host token custody, serialized refresh per connection and atomic token replacement. Rejected/revoked grants require fresh sign-in and verified workspace selection. |

These lifecycle distinctions follow the official [Composio authentication guide](https://docs.composio.dev/docs/authentication) and [connected-account guide](https://docs.composio.dev/kb/guide/platform-connected-accounts). The latter recommends a new auth link rather than the deprecated re-initiation endpoint. ANZ explicitly documents [automatic session timeout and additional authentication for some activities](https://exclusives.anz.com.au/security/protect-yourself/internet-online-banking/); a saved cookie cannot override those controls.

RealBud's [Check access cache](../../server/connected-app-access.ts) refreshes an observation, not provider tokens. Its [MCP broker](../../server/connected-apps-broker.ts) can rebuild a managed transport session once after an explicit **pre-dispatch** `connector_session_expired` refusal. This is also separate from OAuth renewal; an uncertain effect is not replayed automatically.

## Rollout sequence

1. **Choose the supported connection for each source.** Continue Gmail through the existing Composio route. Implement Hermios as a native OAuth/MCP provider, not an invented Composio toolkit. For bank/REI automation, first qualify vendor-supported API access and exact export/import contracts; until then, use the work-browser route with user login. Native browser [download/upload currently rejects](../../server/native-browser-runtime.ts), so persistent login alone does not complete that workflow.
2. **Build the Hermios host connection before enabling Connect.** Establish the supported client/redirect registration, PKCE/state/callback handling, encrypted host storage, refresh, disconnect/revocation and exact request correlation. Keep tokens out of the renderer, prompts and logs. Verify the profile/workspace after consent. Use a new connection generation after reconnect or account/member switch, including A → B → A; discard old responses and approvals while retaining drafts under their original binding.
3. **Expose the native account UI.** Connected apps gets Connect, Check connection, Reconnect and Disconnect plus the verified identity/workspace. Office binds the verified CRM workspace to the RealBud company/member. Department settings assign allowed sources, records, actions and evidence audiences; module enablement alone grants none of these. A user account must not silently become an office-wide credential.
4. **Deliver one read-only native slice.** Mount profile/modules reads and one server-authorized record read, then show it in Desk. Feed Ask and department Buds only host-brokered, scoped tools and selected evidence. The existing module-configuration seam is not a general Bud tool. Prove wrong-workspace, revoked-member, unavailable-field and stale-response rejection before widening access.
5. **Add reviewed effects and concurrent departments.** First ship scoped analysis/drafts. Before CRM writes, require an exact target, current record revision/evidence, effect-time permissions, durable intent/idempotency and ownership across jobs touching the same record. Existing per-case leases alone do not settle external-record concurrency. Preserve uncertain outcomes for readback/reconciliation; do not replay a possibly committed write after refreshing authentication.

The first acceptance milestone is **RealBud-owned sign-in → verified workspace → permitted record read → disconnect**, with refresh/expiry, switching and two-department isolation tests. It does not require claiming all Hermes features, CRM writes, REI imports or unattended bank sessions are complete.

This audit performed only public discovery GETs and source/document reads. It did not register a client, exchange/refresh/revoke tokens, connect an account, call authenticated CRM tools or change the installed app.
