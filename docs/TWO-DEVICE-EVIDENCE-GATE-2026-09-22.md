## Use

```sh
pnpm --silent qa:two-device-evidence --template macos-rehearsal > macos-rehearsal.json
pnpm --silent qa:two-device-evidence --template full-platform > full-platform.json
pnpm qa:two-device-evidence /path/to/receipt.json full-platform
pnpm test:two-device-evidence
```

The default checking target is `full-platform`. Templates contain only `not-run` observations and **fail** validation until actual evidence is recorded. Receipt schema 2 binds the exact contract ID and SHA-256; schema 1 or a stale contract digest requires a fresh template and review, never automatic conversion into acceptance. Preserve existing evidence and failures while mapping observations deliberately to the current requirements.

Every pairing requires six independent workflow runs: morning A (OP-019), morning B (OP-020), bills A and B (two independent OP-026 jobs), bank A (OP-032) and bank B (OP-033). OP-027 remains the additional handoff check. Job and result receipt IDs must be distinct; attempt IDs are scoped to jobs. Each pairing records all applicable cases: 70 for Mac/Mac and 71 for each Windows-containing pair. Only OP-069 is excluded from Mac/Mac. Both mixed directions and Windows/Windows remain required for full-platform.

Participant lists declare minimum observed device/member coverage, with no duplicate or unknown slots. Additional valid corroborating staff slots may appear on a host-only or peer-only case; OP-069 accepts only actual Windows slots and requires every Windows slot. The detailed policy below distinguishes independent runs, shared events and separate privileged actors. A/B labels never grant administrative authority.

Evidence paths resolve inside the receipt directory to nonempty regular files up to 16 MiB. Verification opens a bounded descriptor, checks path/inode binding before and after, hashes the same descriptor and rejects observed replacement/size/metadata changes. This protects the tested replacement paths; it is not a general OS sandbox or a guarantee against every adversarial concurrent filesystem change. Store review evidence in a stable private directory. The checker cannot determine whether evidence contents are truthful, whether a reviewer observed the stated behavior, or whether a supplied artifact actually ran. Those remain independent review duties.

## Roles, evidence modes and scope

- **A** is the host computer running the Accounts member; **B** is the peer running the Property member. They are separate enrolled device identities, member identities, private profiles and provider users. Pairing order is host then peer. These are fixture slots, not universal permissions or mandatory departments.
- **Owner**, **service administrator**, **service operator** and the third uninvited denial-test member are separate actors. A privileged action performed on computer A is not action authority granted to Accounts A. Record actual actor role in evidence. A/B coverage may designate affected staff scopes while a separate operator carries out the fault or administrative operation.
- **I — independent:** both means separately attributed actions/results for each member/device. Different jobs/attempts/source identities must be evidenced where work is independent. One evidence file can contain both clearly separated records; duplicate prose or reusing one worker/job cannot prove two runs.
- **J — joint:** one correlated shared event is sufficient if it includes both actor/view outcomes, exact case/occurrence/revision, and concurrency when the case calls for it. Directional sender/recipient roles do not require both people to perform the same action. Shared event evidence must not count as the second independent business workflow.
- **O — operator:** separate authorized owner/operator acts; evidence observes both staff scopes. Do not require an absent or revoked member to authenticate after revocation. This is not a waiver of observing that member/device's old authority being refused.
- **H — host:** one host setup event on A; full topology matrix supplies both host operating systems. No second company needs to be created on B merely to satisfy the row.
- Combined modes require both portions. **L** means explicitly supported by the named case or literal general specification; **C** means the both-member extension/evidence assignment is a new conservative formalization. **L+C** means the behavior/role is literal but its exhaustive two-member coverage is formalized here. No L label claims an original serialized list was recovered.

The specifications allow pairwise coverage for ordinary layout/format combinations (OP MD 23). Do not turn this report into an unsupported demand for every UI/format Cartesian product. Critical permission, identity, source, native-device and external-effect boundaries must still be explicit. Independent workflow runs do not imply authority to send, pay, sign, issue notices or post real financial records. OP-037 remains externally blocked until its exact manual PMS stage is authorized and observed; local preparation must not pass that stage.
