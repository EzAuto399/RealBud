## Information architecture and job

Keep the established desktop doors: Desk, Work, Schedule and Workspace, including the internal `you` key and existing hashes. Setup remains contextual; it returns to its origin. The website retains its account destinations and bounded sign-in return targets. Billing stays a review destination rather than becoming an effect on Home. There is one home for the action; other screens link to it.

Happy path: an owner verifies the account, reaches the intended company, saves its office details, admits the appropriate people and required connections, then opens the work that is actually ready.

1. Open the intended invite/account task; primary action: **Sign in**. Return to that task, including when the original account was wrong.
2. Open company setup; primary action: **Create and sign in** or **Join and sign in**, according to explicit intent. The host verifies its exact company before accepting credentials or consuming an invitation.
3. Open Office details; primary action: **Save office details**. Keep the draft across a setup detour; show saved and unsaved facts separately.
4. Open People/access in the existing company destination; primary action belongs to the current authorised actor. Staff see who can act, without a credential-entry detour.
5. Open the required connection/readiness destination; primary action completes the current missing prerequisite. Optional connections do not block unrelated work.
6. Return to Desk/Work or the website review destination; primary action names the next review task. Unknown checks remain explicitly unavailable rather than reading as complete.

The sequence is guidance, not an invented prerequisite chain. Existing server facts decide which stages are applicable and which action is admitted.

## Walkthroughs and state contract

First run: enter through the existing invite/company setup, resolve only applicable requirements, see one next action and retain a way back. Returning: resume the destination and scoped draft; refresh facts without exposing a previous identity's result. Power user: retain existing links, keyboard controls and compact routes. Recovery: retry a partial operation with its original identity; do not reinterpret an uncertain commit as failure or silently re-enable an account.

| State | Show | Deliberately avoid | Next action |
|---|---|---|---|
| Loading | Named checks and matching skeleton; retain safe current content | Previous company's invoices or a ready claim | Wait for the current scope; retry on bounded failure |
| Empty | What belongs here and the applicable first task | Fake records or an irrelevant configuration wall | Create/join the company or open the relevant setup destination |
| Sparse/full | Existing list and truthful counts/standing | A layout swap at an arbitrary count | Review the applicable record |
| No results | Query/filter and an exit where that list supports filtering | First-run copy masquerading as a filtered result | Clear or change the filter |
| Partial/unavailable | Name the check that could not complete | "Nothing needs you" from missing evidence | Retry that check or open its destination |
| Wrong account/session expiry | Explain the required identity and preserve a bounded task path | Losing the invite or an arbitrary redirect | Sign out/sign in and return to the task |
| Role denied | Responsible role and an existing navigation/request route | Client-generated permission or shared credentials | Open service administration or request the owner, as applicable |
| Unsaved interruption | Memory-scoped typed changes and unload warning | Writing credentials/drafts to unbound persistent storage | Return to the same draft or explicitly discard |
| Stale revision | Keep typing visible; hold Save | Silent overwrite or substituting a current revision | Reload saved facts or discard the stale draft |
| Partial committed setup | Original identity and precise remaining operation | Reprovisioning an inactive/rebound account | Resume the admitted step or request operator attention |
| Success | Saved result and next applicable destination | A setup receipt promoted to live workflow completion | Continue to the next reviewed task |

Lifecycle/exit: existing permission, expired invite, limits, recovery, sign-out, leave and export routes retain their current authority and data contracts. This round does not create account deletion, an autonomous effect, a new retention promise or a new commercial agreement. Consequential role/network changes remain guarded at the authoritative boundary.
