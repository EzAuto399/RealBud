# Ask composer and response refinement — 1 October 2026

The refinement removes all persistent connected-app names, accounts and status badges from the composer. Connected apps now have a contextual companion card, opened manually from **Context** in the Ask header or automatically when relevant to the current request. Existing background connection availability is preserved. The composer stays focused on the current request, its attachments and its actions.

The card follows the supplied sidebar reference in Ask's paper/ink palette: a compact title, relevant app rows, **View all apps**, and access to Connections. It appears beside the conversation on wide windows and above it on narrower windows. Short landscape windows use a slimmer side column to preserve conversation space. The app list scrolls independently while Hide and the footer stay visible. Opening it never covers the draft, and automatic appearances do not take keyboard focus.

Relevance comes from a known app named in the latest user request, structured app tool activity, app identifiers in existing operation receipts for this thread and request, or a pending sign-in. Assistant prose and generic tool names alone do not establish app use. App activity labels do not imply successful results. Receipts are read when tool activity changes, without adding a polling loop. Missing receipt evidence leaves the panel's existing request and sign-in context intact.

Hide and local Escape dismiss the card; Context reopens it. Dismissal is stored per conversation for the current session and survives streaming, status refreshes, connection errors/recovery, and repeated sign-in for the same app. A new relevant request or newly relevant app can bring it back. Manual opening focuses Hide, closing restores Context, and removed recovery controls keep focus in the card. None of these presentation controls changes account selection, app permissions, sends work, or edits the draft.

The Add flow presents a clear file action and persistent app connections in Ask's existing paper/ink palette. Connected apps have one availability label and an account identity when supplied. Internal tool counts and duplicate readiness copy are removed. Connection recovery opens Connections without starting a chat turn or replacing the user's draft.

The composer uses 44px Add/dictation controls, visible input focus, and responsive action spacing. While work is running, the actions read **Update current work** and **Do next**, with a matching Enter hint. Holding Space or Enter on the dictation control records into the editable draft. Release finishes recording; Escape, lost focus, and cancelled pointer input stop it. Permission replies from a released or replaced hold cannot start recording later.

Responses use real section headings for accessible navigation, a readable prose width, clearer paragraph/list spacing, quieter message chrome and a non-sticky header. Tables preserve numeric alignment and use contained horizontal scrolling at narrow widths. Numbered lists preserve their starting number, task lists retain their semantics, and code remains selectable while streaming. Highlighting uses the light palette. Copying code confirms actual clipboard completion, with a visible failure and retry state.

Bud's response guidance now calls for concise, result-first answers, short paragraphs and selective headings, lists or comparison tables. Large reviews should group repeated findings with verified counts and clearly labelled examples, while retaining material exceptions and requested detail. This is guidance for new model turns, not a rewrite or truncation of saved replies. The renderer preserves complete response content.

Source observations remain evidence-based: stale, revoked, degraded and unselectable-account states never say Available. Sign-in appears in Add even before its service reaches the status response. Account-selection errors keep a retry path. Popup focus remains inside during refresh/account transitions, Tab includes account selection, and Escape returns focus to Add. Outside clicks keep the newly chosen focus. The popup keeps its actions reachable at narrow and short viewport sizes and inherits reduced-motion preferences.

Verification uses production Composer, Toolkit, AskMessage, ChatMarkdown, AskAppContext, draft storage, source store and CSS against an isolated fictional application boundary. All 27 grouped browser checks pass, covering files, accepted submission, current/next work, source recovery, dictation, focus, badge removal, response semantics, clipboard success/failure/retry, streaming, contextual appearance/dismissal, receipt relevance, and narrow, short and desktop layouts. No live app connections or model requests were used. Prompt regressions verify existing behavior; they do not establish the quality of a live model response. The older desk-continuity script received selector updates and syntax validation only.

The final app-context change passes 67 focused frontend tests across seven files, frontend TypeScript, and the production web build with the existing Node 24.21 runtime. Earlier response prompt/evidence regressions also passed. The current change did not rerun the full server suite or exercise live model behavior. The web build retains its existing large-chunk advisory. No desktop package or installed app update was made.
