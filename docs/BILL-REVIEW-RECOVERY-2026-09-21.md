A subsequent Hermes memory-approval audit found an independent security gap; it is fixed and verified in the newer `HERMES-MEMORY-APPROVAL-2026-09-21.md` package. ## Behavior and authority

Bill reviews retain their incomplete form fields and staff notes in individually encrypted `bill-review-draft` workflow records. Opening a new or saved review does not accept a bill. The server owns workspace binding, revision conflicts and immutable request tuples. Saved reviews have bounded pages and exact-ID reads; accepted and discarded records remain readable. Reading an unused workspace creates no records. No plaintext browser storage is used.

Before the first invoice preparation POST, the exact request ID and selected item/message/digest must be acknowledged in durable draft storage. Later “Check the saved proposal request” uses a read-only historical GET. It can show a saved intent, the validated matching run and its output, or an unresolved missing receipt. An intent without a run and an absent intent are not proof that no paid work started. Neither case triggers an automatic preparation retry. Manual source review and saving for later remain available.

The editor coordinator serializes revision-checked saves. Lost acknowledgements require matching direct readback. Concurrent-window conflicts retain local notes and offer a separate copy while keeping the same proposal identity. Source confirmations are never persisted as authority: reopening rereads evidence and requires staff confirmation again. The application warns before closing while a draft has unacknowledged edits.

Backup uses the same draft validator as live storage, verifies workspace/revision and any present proposal link, and rekeys drafts to the destination workspace key. A missing proposal intent remains valid because saving the draft deliberately precedes dispatch. Extra approval fields, foreign workspaces and mismatched present intents fail closed before staging. Existing backup capacity limits remain unchanged.

## Limits

Drafts are recovery hints, not authoritative bills or approvals. A process/OS failure before a save acknowledgement can lose the latest unsaved keystrokes; the UI must not call them saved. Per-field and 64 KiB plaintext/envelope limits bound each draft, without a lifetime record cap. Historical lookup does not reconcile a missing worker admission into a definitive no-work receipt. Live customer Gmail/bank/REI, Windows/native key custody, signed distribution, managed billing deployment and long office operation remain separate proof gates.
