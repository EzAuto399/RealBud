# Reviewed instruction history archival — 22 September 2026

This checkpoint implements the separate [instruction-history plan](SKILL-HISTORY-ARCHIVAL-PLAN-2026-09-22.md). Pack configuration archival remains a distinct feature. The reusable RealBud goal stays active; this work does not commission a customer account or release a production build.

## Behavior

A customer can review older instruction revisions under Schedule → Import packs → Bud’s instruction improvements. Archival keeps the active instruction and two newest revisions immediately available, with every older revision retained in immutable private storage. The review lists the revisions being moved and requires confirmation. Current instruction bytes, recipe revisions, approval, schedules and saved business records stay unchanged.

History is browsed in bounded metadata pages, with complete instruction text fetched for a selected revert. A reviewed revert appends a new revision through the existing durable instruction-update path, pauses dependent plans, clears their approval and turns schedules off. Exact installation, history source, revision, digest and review preconditions prevent stale selection or an A→B→A change from reusing an old decision. A lost reply refreshes the persisted state; an interrupted archive offers a specific recovery action.

## Storage and recovery

`customer-skill-history/<pack>/<digest>.json` contains immutable instruction batches. Each override carries its own verified head; configuration snapshots retain those heads, including removed and later reintroduced skills. Archival persists a compact intent before writing and checking the immutable file, then publishes the head and prunes only the now-archived inline text. A restart uses the saved decision. Owned partial temporary files can be reconciled; unknown, linked or conflicting content is preserved and held for recovery.

The first skill archive writes journal format 2. Earlier version-1 code rejects this root instead of silently losing the new archive reference. The normal journal limit remains 2,000,000 bytes. A validated compact pending intent may borrow at most 16 KiB over an otherwise admitted journal; its completion must return to the normal bound. The private writer accepts the larger existing journal only with explicit size and semantic admission at this call site. Other callers retain their previous bound.

Live and backup graph validation inspect current, recent and archived configuration roots, while caching only immutable batch metadata. Shared heads are valid; every root still has its own identity/count/order checks. Missing, detached, foreign, cyclic or hash-invalid records fail admission. An independent reproduction also found that a later retained revision could contradict the active digest recorded by an earlier archive. Validation now carries the small number of unresolved digest commitments through each lineage and rejects that contradiction without merging independent removal/reintroduction histories.

The same format gate also applies when the only remaining skill head is inside an archived configuration. A reproduced case previously passed live reads after the root was changed to version 1; live and backup admission now both reject it. Pending instruction updates are admitted before side effects only when they continue the current revision, retain the complete dependent-plan set and carry a consistent reviewed target and scope. Legacy readable metadata stays readable, but must be canonical before archival.

The existing authenticated customer-pack dispatcher, settings fences and backup snapshot barrier cover these routes. A pending archive holds conflicting pack execution/mutations and backup capture. Restored archive scope is audit provenance; it does not authorize execution in the destination workspace. Restore retains instruction history and continues to invalidate approvals and schedules.
