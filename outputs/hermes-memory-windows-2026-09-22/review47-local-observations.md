# Local observations accompanying the bounded Grok 4.7 review

Scope: only `hermes-memory-windows.py` and `hermes-memory-windows-native.py`; cooperative native writers, local fixed NTFS, production hold unchanged. No Windows APIs or real profiles were exercised by these local probes.

1. **Raw host-lock exceptions escaped the protocol boundary.** On the reviewed protocol snapshot, `_mutation` forwarded lock enter/exit exceptions directly. The synthetic public `write_new` probe raised `OSError` with its synthetic private-path marker intact (`review47-local-checks.json`). Root subsequently added fixed error mapping with suppressed context, preserving recognized native codes. Four checks on protocol SHA256 `e838beb06d5c5f132db4e1f5158f97d72b4e7dd90e55eb4a03a7e42f280c8bfa` passed: lock enter, lock exit, recognized code preservation, and public write entry (`review47-lock-fix-check.json`). **Resolved in owner's later source; the Grok packet retains the original snapshot.**

2. **The old deletion comment overstated the postcondition.** `delete_exact` originally said deletion completes when its owned handle closes. An already-open compatible reader can defer ordinary deletion beyond that close; deletion is finalized after the last relevant handle closes. The native backend correctly promises only disposition and its own handle release. Root changed the protocol return to `deletion-requested` and requires caller name/journal reconciliation before terminal cleanup. There are no production callers yet. **Contract corrected; actual Windows pending-deletion/reconciliation behavior is still an execution gate.** [Microsoft DeleteFileW semantics](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-deletefilew).

No additional native defect was established in this local scan. In particular, the self-relative security descriptor check matches Microsoft's stated format for returned descriptors; demanding an absolute-descriptor parsing fallback would not be supported by that contract. [Microsoft descriptor formats](https://learn.microsoft.com/en-us/windows/win32/secauthz/absolute-and-self-relative-security-descriptors).

The independently frozen Grok packet and all post-snapshot changes are preserved separately. `review47-post-snapshot.diff` records the root's two fixes and the native owner's two additional guards (nonempty new-file rejection and DWORD/64-bit metadata bounds). This is code-review evidence, not actual Windows execution or release signoff.
