# Scoped department execution authority

Implemented company authority for exactly one assigned case and exact recipe/executor. Member creates the grant and supplies a pre-persisted 256-bit secret; current owner confirms the immutable spec digest. Grant identity/source/deadlines are server-derived. Maximum duration is seven days; company-wide historical grant capacity is 1,000, matching bounded owner pagination. Only secret hashes reach the database. No general member session is stored or accepted by the background APIs.

One admission consumes each grant. Independent grants racing for the same case serialize on its department/case locks: only one can claim the expected fence. The client supplies the private claim secret and execution/request IDs before sending. Original admission receipt is immutable; replay does not regenerate secrets or extend deadlines. Renewal has its own immutable operation ID/receipt, extends the current lease at most five minutes from authoritative database time and never beyond grant expiry, and never changes the original dispatchBefore. check returns current lease plus only current case title/description. The controller must enforce dispatchBefore for first enqueue; ongoing work uses renewable lease checks.

Background lookup uses a transaction-local hash predicate for the candidate grant, then resolves an active real member under company lifecycle/member locks and switches to normal member RLS. Hash lookup context is explicitly cleared. Certificate gate wraps the whole transaction through COMMIT. Department, source, case fence, assignment, member/owner epochs, certificate and host incarnation are checked under the existing locks. Role/active changes increment a durable member epoch; lifecycle triggers revoke affected grants and fence claims, so permission/ownership A-B-A cannot revive them.

All settlements (prepared/interrupted/failed) hold the case in recovery_required. They never mark done/released. An identical settlement can be retried only while that same recovery fence remains current; expired/revoked grants or later human recovery reject stale settlement. The desktop journal remains responsible for retaining factual results when host delivery is denied. Explicit owner recovery remains the existing department API.

Migration0008 is additive. Backup preserves grant/claim/event history but revokes restored grants, rotates host incarnation and holds in-flight cases. Exact trusted0005/0006/0007 snapshots upgrade with no implicit grants and epoch0 defaults; forged added fields remain denied. Raw executor secrets are not stored in these database records; the installation owns exclusion of private credential files from portable backups.

Verification: 23 actual disposable PostgreSQL tests passed across department-execution.integration.test.ts and backup.integration.test.ts, including independent-pool races, two competing grants for one case, observed lifecycle-lock revocation, retries, renewable/fixed deadlines, expiry, source-only reads, scope separation, sessionless operation, permission/ownership ABA and restore compatibility. Server TypeScript passed. Earlier first/previous receipts are preserved. Root owns independent PG/TLS encrypted-client tests and final product integration.

Authority purpose is local-department-prepare-v1. This does not authorize website work, provider access, arbitrary knowledge reads or external writes. Durable single admission is not a guarantee of exactly-once external effects; worker idempotency or explicit recovery remains necessary.
